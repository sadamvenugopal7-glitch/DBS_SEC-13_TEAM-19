Problem Statement & Objective

Traditional wine inventory management suffers from stock discrepancies, unmonitored supplier relationships, and lack of atomic transaction guarantees during high-volume sales orders. The Wines Management System establishes a normalized relational schema (3NF) that eliminates update anomalies, maintains referential integrity through foreign key cascades/restrictions, and guarantees ACID compliance during multi-item order placement.

System Architecture
Browser (HTML5 / Vanilla CSS3 / JS / Bootstrap 5 / Chart.js)
   │
   ▼  REST API (HTTP / JSON / CSV Streams)
Python 3 Flask Backend (Modular Blueprints, Connection Pool, Input Validator)
   │
   ▼  mysql-connector-python (ACID Transactions, Parameterized SQL)
MySQL 8.x Relational Database (wines_management_db)
DBMS Engineering Features Implemented
  • Entity Relationship Modeling: 6 core tables with strict PKs and FKs.
  • 3NF Normalization: Zero transitive or partial dependencies.
  • Generated Stored Columns: subtotal STORED in MySQL.
  • Transactions: START TRANSACTION, COMMIT, ROLLBACK.
  • Relational Views: 5 analytical views for stock & sales.
  • Stored Procedures: 5 procedures for stock adjustments.
  • Triggers: 3 integrity triggers enforcing positive stock.
  • Performance Indexes: B-Tree indexes on search & FK keys.
